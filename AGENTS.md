# AGENTS.md: Rioku Labs website

Instructions for AI coding tools (Codex, Cursor, Claude Code and others) and a quick orientation for people. Read this before changing anything.

The Rioku Labs site (rioku.dev): a Strapi 5 CMS in cms/ and an Astro static site in web/. Public repository; the real privacy lists and private seed entries stay in gitignored local files.

## Layout

- `cms/` Strapi 5 (schemas, seed, tests). `web/` Astro 7 static site (pages, components, scripts, unit and e2e tests).
- `brand/` logo sources. `tools/` repo scripts. Spec and build ledger live in the workspace under `docs/website/`, not in this repo.

## Build and test

```bash
npm run install:all
( cd cms && npm run check && npm run test:acceptance && npm run build )
( cd web && npm test && npx astro check && npm run build && npm run test:e2e )
```

`scripts/test.sh` runs the offline checks. CI runs the same on GitHub-hosted runners, which have no game, SDK or Blender.

## Code style

- TypeScript and Astro; 2-space indent (see `.editorconfig`). Follow the neighbouring file.
- Visible text in plain language, specific and short. No hype, no filler.
- Everything is visibility-gated: new collections default to private.

## Rules for this repo's data and assets

- Never make a private or draft entry reachable: the build asserts this with canary entries; keep that test passing.
- Art is our own. Game trademark notices stay on game pages.
- `web/src/config/identity.json` is the one place for name, domain and org.
- Fixtures under `web/fixtures/` drive CI so it never needs Strapi or secrets.

## Commits and changelog

- Conventional Commits: `type(scope): summary` (feat, fix, docs, style, refactor, perf, test, build, ci, chore, revert). Release notes and the changelog are generated from them with git-cliff (`scripts/changelog.sh`).
- Sign off commits with `git commit -s` (DCO). The project is GPL-3.0. Outside contributors also sign the Rioku Labs CLA once (`CLA.md` in riokulabs/.github); the `cla` workflow checks it. Never add `actions/checkout` or any step that runs pull request code to `.github/workflows/cla.yml`.
- Optional hooks: `scripts/install-hooks.sh`.

## Never

- Never add AI attribution anywhere: no `Co-Authored-By` trailer for an AI tool, no "generated by/with" notes in commits, pull requests, code or docs.
- Never commit decompiled Keen code, Keen DLLs or other game binaries.
- Never copy Keen assets beyond the vanilla reuse this repo already documents, and never use third-party content that has no license.
- Never commit secrets or tokens (for example the SeMcp2 bearer token, Steam or GitHub credentials, `.env` files).
- Never push, tag or publish (GitHub, Steam Workshop, deploys) unless the maintainer asked for it in this session.
- Never modify the game install or the Steam library directories. Treat them as read-only.
- Never add deploy steps to CI or run a deploy yourself. The one exception is the maintainer-approved GitHub Pages workflow (`.github/workflows/pages.yml`), which builds the static site from Strapi and deploys it to Pages; don't add other deploy targets, and don't change its triggers, secrets or gates without the maintainer's approval in the session. Everything else about deploying is manual.
- Never put credentials in `cms/.env.example`, fixtures or docs.
- Never rewrite published history or force-push shared branches.
